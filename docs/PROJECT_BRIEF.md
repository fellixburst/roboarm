# 项目构想与需求

## 使用目标

用户在电脑或手机上打开控制台，查看相机画面、机械臂状态和小车状态，选择设备后进行手动操作。设备连接、故障与停止状态必须可见。后续可以把手动动作组合成任务，并加入视觉识别、示教数据和学习策略。

初期服务个人使用，界面使用中文。优先复用现有 SO101 和电脑，采购决定以实际接口、供电与传图测试为依据，不预先指定昂贵的车载计算平台。

## 构想来源与已知边界

| 来源 | 可确认的信息 | 仍需核实的信息 |
| --- | --- | --- |
| 设备清单讨论 | 用户表示已有 SO101 主从臂及一个相机 | 装配、标定、遥操作和采集是否已跑通 |
| 移动集成方案讨论 | 用户要求电脑不装上车，通过 Wi-Fi 控制；已有机械臂控制板；考虑后续云台，关注主控成本 | 底盘型号、预算、主控板、相机最终规格 |
| 开发环境讨论 | 用户报告 Ubuntu 无法识别 Wi-Fi 网卡 | 故障是否解决；此前助手提及的驱动诊断和软件环境需现场复核 |
| 本次项目要求 | 整理构想，建立 GitHub 项目，转入云端开发网页控制功能 | 仓库地址和云端运行环境 |

历史助手提及双目相机已下单，以及 LeRobot、PyTorch、NVIDIA 环境已有配置；本次读取的用户文字和本地文件不足以独立确认，因此不列为已验收成果。现有单相机与所讨论双目相机是否同一设备，也待确认。

## 网页操作流程

1. 进入控制台，默认显示模拟模式或未连接状态。
2. 选择设备，检查连接、标定、限位和当前控制权。
3. 用户主动启用控制，开始点动或驾驶；持续显示反馈与命令结果。
4. 松开小车方向按钮、页面失焦或控制会话失效时停止发送运动意图；设备端独立执行超时停车。
5. 故障或停止后保持禁用，恢复连接也不自动继续动作，需要用户重新启用。

## 功能要求

| 模块 | 第一版 | 后续扩展 |
| --- | --- | --- |
| 设备管理 | 模拟机械臂、模拟小车、相机占位状态，设备能力查询 | 真机发现、设备配置、多机器人 |
| 机械臂 | 关节点动、夹爪控制、限位校验、状态反馈 | 主从遥操作、动作录制、轨迹回放 |
| 小车 | 方向操作、速度上限、按住运行、松开停止 | 里程计、导航与路径执行 |
| 相机 | 模拟预览与抓图交互 | 真机视频、双目标定、定位与云台 |
| 任务 | 手动控制和明确的命令生命周期 | 停车、识别、抓取、放置流程 |
| 数据 | 操作日志、故障记录 | 示教数据集、训练任务、模型版本 |

命令状态至少区分已接收、已拒绝、执行中、已完成和失败；接收到请求不能显示为动作已完成。

## 控制边界

浏览器负责操作意图，不承担电机实时闭环。实际限速、限位、命令有效期及失联响应必须在设备侧落实。只允许一个会话持有运动控制权，其他会话可查看状态。

小车超时进入零速度目标；机械臂停止策略按机构负载、舵机能力和实际测试确定，不能把直接断扭矩当作通用停止方式。网页停止按钮属于软件停止，物理急停与电源切断需单独设计和验证。

相机流与控制消息分开处理，网络拥塞时旧运动指令不得排队后继续执行。重连后废弃旧会话命令，重新获取控制权和启用。

## 硬件信息补充表

| 项目 | 待补充内容 | 影响 |
| --- | --- | --- |
| SO101 | 控制板、舵机类型、串口标识、标定文件、供电规格 | 真机驱动和关节约束 |

| 车载主控 | 预算、USB、Wi-Fi、供电、系统架构 | 移动化部署 |
| 机械集成 | 安装高度、工作范围、重心、电池与配电 | 抓取地面物品和稳定性 |

这些信息不阻碍模拟版开发，但对应真机功能在信息和测试齐备之前不得标为完成。
